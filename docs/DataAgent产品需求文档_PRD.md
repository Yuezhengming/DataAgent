## 1. 产品概述

### 1.1 产品简介

**DataAgent** 是阿里云数据管理服务 (DMS) 推出的企业级数据智能体产品，基于大语言模型 (LLM) 和 AI Agent 技术，为企业提供自然语言交互的数据查询、分析和洞察能力。

### 1.2 产品愿景

让每个业务人员都能像与数据专家对话一样，轻松获取数据洞察，实现"人人都是数据分析师"的目标。

### 1.3 核心价值主张

- **降低数据使用门槛**：无需编写 SQL，通过自然语言即可查询数据
- **提升数据价值交付效率**：从传统的"提需求-开发-交付"模式转变为"即问即答"
- **智能化数据洞察**：AI 自动发现数据规律、异常和趋势
- **企业级安全可控**：基于 DMS 的权限体系，确保数据访问安全合规

### 1.4 产品背景

随着企业数字化转型深入，数据已成为核心资产。但传统数据分析面临以下痛点：

1. **技术门槛高**：业务人员需要学习 SQL、理解数据库结构
2. **响应周期长**：需要数据团队介入，从需求到交付周期长
3. **资源浪费**：大量重复性数据查询占用数据团队时间
4. **数据孤岛**：跨部门、跨系统数据难以整合分析

DataAgent 通过 AI 技术解决这些痛点，实现数据民主化。

## 2. 市场分析

### 2.1 市场规模

- **全球数据分析市场**：预计 2025 年达到 $420 亿美元
- **中国企业数据管理市场**：年增长率超过 30%
- **AI + 数据分析市场**：新兴赛道，预计 3 年内达到 $50 亿美元

### 2.2 市场趋势

1. **数据民主化**：让非技术人员也能使用数据
2. **AI 原生应用**：大模型技术在企业应用中快速落地
3. **自然语言交互**：NL2SQL 技术成熟度提升
4. **实时数据分析**：从离线报表转向实时洞察
5. **Data Fabric**：统一的数据访问层成为趋势

### 2.3 目标市场

- **行业**：金融、电商、零售、制造、互联网、政务
- **企业规模**：中大型企业（500+ 员工）
- **地域**：中国大陆，逐步扩展至海外

### 2.4 市场机会

- 阿里云生态内数百万企业客户
- DMS 已有用户基础，可快速转化
- 企业对 AI 应用的接受度快速提升
- 数据治理需求增长带来的市场机会

## 3. 用户画像与需求

### 3.1 核心用户角色

#### 角色 1：业务分析师

**基本信息**
- 年龄：25-35 岁

- 技术能力：Excel 熟练，SQL 基础或不会

- 等待数据团队响应时间长
- 数据口径理解困难
- 跨表关联查询复杂

- 监控关键指标变化
- 导出数据用于汇报

**痛点**
- 完全不懂 SQL
- 需要频繁打扰数据团队

- 无法自主探索数据

- 教育背景：本科及以上，计算机相关专业

- 提升 SQL 编写效率

- 减少重复性查询工作

**痛点**

- 需要维护大量临时查询脚本

- 数据血缘追溯困难

- 快速了解业务全貌
- 数据驱动决策
- 监控核心业务指标
- 发现业务机会和风险

**痛点**
- 依赖下属提供数据
- 数据时效性差
- 无法深入探索数据

## 4. 产品定位

### 4.1 产品定位陈述

DataAgent 是面向企业的 **AI 驱动的数据智能助手**，通过自然语言交互，让业务人员无需编写 SQL 即可快速获取数据洞察，同时为数据开发者提供智能化的开发辅助工具。

### 4.2 差异化优势

1. **深度集成 DMS 生态**
   - 复用 DMS 的权限体系、数据源管理
   - 无缝对接企业现有数据基础设施
   - 统一的数据治理和安全合规

2. **企业级 AI 能力**
   - 基于阿里云通义大模型
   - 支持私有化部署和数据隔离
   - 可定制化的行业模型

3. **智能元数据理解**
   - 集成 OneMeta 元数据服务
   - 自动理解表结构、字段含义、业务口径
   - 支持数据血缘和影响分析

4. **全链路数据安全**
   - 基于 DMS 的细粒度权限控制
   - 数据脱敏和水印
   - 完整的操作审计

### 4.3 产品边界

**包含的功能**
- 自然语言转 SQL (NL2SQL)
- 数据查询和分析
- 数据可视化
- 智能数据洞察
- 查询历史和管理

**不包含的功能**
- 数据建模和 ETL（由 DMS 其他模块提供）
- 机器学习模型训练（可集成 PAI 平台）
- 实时数据流处理（由 Flink 等产品提供）
- BI 报表系统（可集成 QuickBI）

### 5.2 核心功能列表

#### 5.2.1 自然语言查询 (NL2SQL)

**功能描述**
用户使用自然语言提问，系统自动转换为 SQL 并执行查询。

**核心能力**
- 支持中英文自然语言输入
- 自动识别查询意图（查询、统计、对比、趋势等）
- 智能表关联和字段映射
- 支持复杂查询（多表关联、子查询、聚合等）
- SQL 优化和执行计划分析

**示例场景**
- "查询最近7天的订单总额"
- "对比本月和上月的销售额增长率"
- "找出销售额前10的商品"
- "分析用户活跃度的地域分布"

#### 5.2.2 智能数据可视化

**功能描述**
根据查询结果自动推荐最合适的图表类型，并生成可视化展示。

**核心能力**
- 自动识别数据类型和维度
- 智能推荐图表类型（折线图、柱状图、饼图、散点图等）
- 支持交互式图表（缩放、筛选、钻取）
- 支持多图表组合展示
- 图表样式自定义

**支持的图表类型**
- 折线图：趋势分析
- 柱状图：对比分析
- 饼图：占比分析
- 散点图：相关性分析
- 热力图：分布分析
- 漏斗图：转化分析
- 地图：地域分析

#### 5.2.3 对话式交互

**功能描述**
支持多轮对话，理解上下文，实现连续的数据探索。

**核心能力**
- 上下文理解和记忆
- 追问和细化查询
- 查询结果的二次分析
- 自然语言反馈和确认
- 错误理解的纠正机制

**交互示例**
```
用户: 查询本月订单数
Agent: 本月共有 15,234 个订单

用户: 按地区分组
Agent: [展示各地区订单数分布]

用户: 只看前5名
Agent: [展示订单数前5的地区]

用户: 对比上月
Agent: [展示本月vs上月前5地区对比]
```

#### 5.2.4 智能洞察分析

**功能描述**
AI 自动分析数据，发现异常、趋势和规律，主动提供洞察。

**核心能力**
- 异常检测：识别数据异常波动
- 趋势分析：预测未来趋势
- 相关性分析：发现数据间关联
- 同比环比：自动计算增长率
- 智能摘要：生成数据分析报告

**洞察类型**
- 📈 趋势洞察："销售额呈上升趋势，月增长率15%"
- ⚠️ 异常洞察："昨日订单量下降30%，需关注"
- 🔍 关联洞察："用户活跃度与购买转化率正相关"
- 💡 建议洞察："建议增加华东地区营销投入"

#### 5.2.5 数据源管理

**功能描述**
统一管理企业内多个数据源，支持跨库查询。

**核心能力**
- 多数据源接入和管理
- 数据源健康监控
- 跨库关联查询
- 数据源权限隔离
- 连接池管理

**支持的数据源**
- 关系型数据库：MySQL、PostgreSQL、Oracle、SQL Server
- 云原生数据库：PolarDB、AnalyticDB
- 数据仓库：MaxCompute、Hive、ClickHouse
- NoSQL：Redis、MongoDB
- 对象存储：OSS

#### 5.2.6 查询历史与管理

**功能描述**
记录所有查询历史，支持快速复用和审计。

**核心能力**
- 查询历史记录
- 收藏常用查询
- 查询分类和标签
- 查询分享和协作
- 查询性能分析

#### 5.2.7 数据导出

**功能描述**
支持将查询结果导出为多种格式。

**支持格式**
- Excel (.xlsx)
- CSV (.csv)
- JSON (.json)
- PDF 报告
- 图片 (.png, .jpg)

**导出选项**
- 全量导出 / 部分导出
- 数据脱敏导出
- 定时导出
- 批量导出

### 6.3 NL2SQL 技术方案

#### 6.3.1 处理流程

```
用户输入
   ↓
意图识别 → 确定查询类型（查询/统计/对比/趋势）
   ↓
实体抽取 → 识别表名、字段名、条件值
   ↓
元数据检索 → 从 OneMeta 获取表结构和业务含义
   ↓
SQL 生成 → 基于大模型生成 SQL
   ↓
SQL 优化 → 执行计划分析和优化
   ↓
权限校验 → 检查用户数据访问权限
   ↓
执行查询 → 在目标数据库执行
   ↓
结果处理 → 数据脱敏、格式化
   ↓
可视化推荐 → 推荐合适的图表类型
   ↓
返回结果
```

## 1. 产品概述

### 1.1 产品定义

**DataAgent** 是一个基于 Spring AI Alibaba 框架的企业级智能数据分析平台，通过自然语言处理（NLP）和大语言模型（LLM）技术，将用户的自然语言查询自动转换为 SQL 查询（NL2SQL），并提供智能数据分析、可视化和报告生成能力。

### 1.2 核心价值主张

| 价值点               | 说明                                           | 受益方             |
| -------------------- | ---------------------------------------------- | ------------------ |
| **降低数据分析门槛** | 非技术人员无需学习 SQL，用自然语言即可查询数据 | 业务人员、产品经理 |
| **提升分析效率**     | 自动化 SQL 生成和数据分析流程，节省 80% 时间   | 数据分析师         |
| **智能化决策支持**   | AI 驱动的数据洞察和自动报告生成                | 管理层、决策者     |
| **多租户支持**       | 支持多个智能体独立配置，满足不同业务场景       | 企业 IT 部门       |
| **知识沉淀**         | 业务知识库和语义模型持续优化查询准确性         | 整个组织           |

### 1.3 产品特色

- ✅ **Graph 工作流引擎**：15 个节点的智能编排，支持动态路由和错误重试
- ✅ **人工审核机制**：关键 SQL 执行前可人工确认，确保数据安全
- ✅ **流式输出**：实时反馈执行进度，提升用户体验
- ✅ **知识增强**：业务知识库 + 语义模型双重增强理解能力
- ✅ **多数据源支持**：支持 MySQL、PostgreSQL、ClickHouse 等
- ✅ **Python 分析**：自动生成和执行 Python 代码进行深度分析

### 2.1 市场背景

**数据驱动决策**已成为企业核心竞争力，但存在以下痛点：

| 痛点           | 现状                                | 影响                   |
| -------------- | ----------------------------------- | ---------------------- |

| **重复劳动**   | 相似查询需要反复编写 SQL            | 浪费人力资源           |
| **知识孤岛**   | 业务知识分散，难以复用              | 新人上手慢，错误率高   |
| **数据安全**   | 直接访问数据库存在风险              | 误操作可能导致数据损失 |

### 5.3 自然语言查询（NL2SQL）

#### 5.3.1 功能描述

核心功能，将用户的自然语言查询转换为 SQL 并执行，返回结果。

#### 5.3.2 功能需求

| 功能点             | 需求描述                      | 优先级 | 状态 |
| ------------------ | ----------------------------- | ------ | ---- |
| **查询重写**       | 理解用户意图，重写查询        | P0     | ✅    |
| **关键词提取**     | 提取查询中的关键实体和时间    | P0     | ✅    |
| **Schema 召回**    | 从向量库召回相关表和字段      | P0     | ✅    |
| **SQL 生成**       | 生成可执行的 SQL 语句         | P0     | ✅    |
| **SQL 执行**       | 执行 SQL 并返回结果           | P0     | ✅    |
| **语义一致性校验** | 校验 SQL 结果是否符合用户意图 | P0     | ✅    |
| **流式输出**       | 实时反馈执行进度              | P0     | ✅    |
| **错误重试**       | SQL 错误时自动重试            | P0     | ✅    |
| **复杂查询**       | 支持多表关联、聚合、子查询    | P1     | ✅    |
| **时间表达式**     | 支持"最近一周"等自然语言时间  | P1     | ✅    |
| **模糊匹配**       | 支持同义词和拼写纠错          | P1     | ✅    |

#### 5.3.3 Graph 工作流

DataAgent 使用 15 个节点的 Graph 工作流编排 NL2SQL 流程：

```
1. QueryRewriteNode - 查询重写
2. KeywordExtractNode - 关键词提取
3. SchemaRecallNode - Schema 召回
4. TableRelationNode - 表关系分析
5. PlannerNode - 计划生成
6. PlanExecutorNode - 计划执行
7. SqlGenerateNode - SQL 生成
8. SqlExecuteNode - SQL 执行
9. SemanticConsistencyNode - 语义一致性校验
10. PythonGenerateNode - Python 代码生成
11. PythonExecuteNode - Python 代码执行
12. PythonAnalyzeNode - Python 结果分析
13. ReportGeneratorNode - 报告生成
14. HumanFeedbackNode - 人工审核
15. END - 结束节点
```

#### 5.3.4 用户故事

```
作为业务分析师，
我希望输入"查询最近一周销售额最高的前10个产品"，
系统能够自动生成 SQL 并返回结果。
```

#### 5.3.5 验收标准

- [ ] 简单查询准确率 > 90%
- [ ] 复杂查询准确率 > 80%
- [ ] 查询响应时间 < 5 秒（P95）
- [ ] 支持至少 10 种常见查询模式
