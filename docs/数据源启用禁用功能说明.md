# 数据源启用/禁用功能说明

## 问题描述

用户反馈：上传的数据源，在数据源列表中点击"启用/禁用"按钮操作失效。

---

## 问题原因

### 1. 系统设计限制

系统设计为：**一个智能体同时只能启用一个数据源**。

这是因为：
- 数据分析需要明确的数据来源
- 避免多个数据源之间的表名冲突
- 简化 Schema 召回和 SQL 生成逻辑

### 2. 原有实现问题

**后端逻辑（修复前）：**

在 `AgentDatasourceServiceImpl.toggleDatasourceForAgent()` 方法中：

```java
if (isActive) {
    int activeCount = agentDatasourceMapper.countActiveByAgentIdExcluding(agentId, datasourceId);
    if (activeCount > 0) {
        throw new RuntimeException("同一智能体下只能启用一个数据源，请先禁用其他数据源后再启用此数据源");
    }
}
```

**问题：**
- 如果已有启用的数据源，直接抛出异常
- 用户需要先手动禁用其他数据源，再启用目标数据源
- 操作繁琐，用户体验差

**前端逻辑（修复前）：**

```javascript
const changeDatasource = async (row : Datasource, active : boolean) => {
  const response = await agentDatasourceService.toggleDatasourceForAgent(...)
  if(response.success) {
    row.status = active ? 'active' : 'inactive'  // 直接修改对象属性
  }
}
```

**问题：**
- 直接修改 `row.status` 可能不会触发 Vue 的响应式更新
- 没有重新加载数据源列表，导致界面状态不同步
- 错误处理不够友好

---

## 解决方案

### 1. 后端优化：自动禁用其他数据源

**修改文件：** `spring-ai-alibaba-data-agent-management/src/main/java/com/alibaba/cloud/ai/service/impl/AgentDatasourceServiceImpl.java`

**修改内容：**

```java
@Override
@Transactional
public AgentDatasource toggleDatasourceForAgent(Integer agentId, Integer datasourceId, Boolean isActive) {
    // If enabling data source, automatically disable other data sources
    if (isActive) {
        log.info("启用数据源 {} for agent {}, 自动禁用其他数据源", datasourceId, agentId);
        // Disable all other data sources for this agent
        agentDatasourceMapper.disableAllByAgentId(agentId);
    }

    // Update data source status
    int updated = agentDatasourceMapper.updateRelation(agentId, datasourceId, isActive ? 1 : 0);

    if (updated == 0) {
        throw new RuntimeException("未找到相关的数据源关联记录");
    }

    log.info("数据源状态更新成功: agentId={}, datasourceId={}, isActive={}", agentId, datasourceId, isActive);

    // Return the updated association record
    return agentDatasourceMapper.selectByAgentIdAndDatasourceId(agentId, datasourceId);
}
```

**改进点：**
- ✅ 移除了抛出异常的逻辑
- ✅ 启用数据源时，自动禁用其他所有数据源
- ✅ 添加了事务注解 `@Transactional`，确保操作原子性
- ✅ 添加了日志记录，便于调试

### 2. 前端优化：重新加载数据 + 用户提示

**修改文件：** `spring-ai-alibaba-data-agent-frontend/src/components/agent/DataSourceConfig.vue`

**修改内容：**

```javascript
const changeDatasource = async (row : Datasource, active : boolean) => {
  const datasourceId = row.id;
  
  // 如果是启用操作，检查是否有其他启用的数据源
  if (active) {
    const activeCount = datasource.value.filter(d => d.status === 'active' && d.id !== datasourceId).length
    if (activeCount > 0) {
      try {
        await ElMessageBox.confirm(
          '启用此数据源将自动禁用其他已启用的数据源，是否继续？',
          '提示',
          {
            confirmButtonText: '确定',
            cancelButtonText: '取消',
            type: 'warning'
          }
        )
      } catch {
        return // 用户取消操作
      }
    }
  }
  
  try {
    const response : ApiResponse = await agentDatasourceService.toggleDatasourceForAgent(props.agentId, { datasourceId: datasourceId, isActive: active});
    if(response.success) {
      ElMessage.success(active ? '数据源已启用，其他数据源已自动禁用' : '数据源已禁用')
      // 重新加载数据源列表以确保状态同步
      await loadAgentDatasource()
    } else {
      ElMessage.error(response.message || '操作失败！')
      console.error('Failed to change datasource:', response)
    }
  } catch (error: any) {
    const errorMsg = error?.response?.data?.message || error?.message || '操作失败'
    ElMessage.error(errorMsg)
    console.error('Failed to change datasource:', error)
  }
}
```

**改进点：**
- ✅ 启用数据源前，检查是否有其他启用的数据源
- ✅ 如果有，弹出确认对话框，告知用户会自动禁用其他数据源
- ✅ 操作成功后，重新加载数据源列表（`await loadAgentDatasource()`）
- ✅ 确保界面状态与后端数据同步
- ✅ 改进了错误处理，显示更友好的错误信息

## 使用说明

### 启用数据源

1. 在数据源列表中，找到要启用的数据源
2. 点击"启用"按钮
3. 如果当前有其他启用的数据源，会弹出确认对话框
4. 点击"确定"后：
   - 目标数据源被启用
   - 其他数据源自动禁用
   - 列表自动刷新，显示最新状态

### 禁用数据源

1. 在数据源列表中，找到要禁用的数据源（状态为"启用"）
2. 点击"禁用"按钮
3. 数据源立即被禁用
4. 列表自动刷新

## 技术细节

### 数据流程

```
用户点击"启用"按钮
    ↓
前端检查是否有其他启用的数据源
    ↓
如果有，弹出确认对话框
    ↓
用户确认
    ↓
调用后端 API: PUT /api/agent/{agentId}/datasources/toggle
    ↓
后端自动禁用其他数据源
    ↓
后端更新目标数据源状态
    ↓
返回成功响应
    ↓
前端重新加载数据源列表
    ↓
界面更新，显示最新状态
```

### 数据库操作

**禁用所有数据源：**
```sql
UPDATE agent_datasource 
SET is_active = 0 
WHERE agent_id = ?
```

**启用目标数据源：**
```sql
UPDATE agent_datasource 
SET is_active = 1 
WHERE agent_id = ? AND datasource_id = ?
```

### 事务保证

使用 `@Transactional` 注解确保：
- 禁用所有数据源
- 启用目标数据源

这两个操作要么全部成功，要么全部回滚，保证数据一致性。

## 常见问题

### Q1: 为什么一个智能体只能启用一个数据源？

**A:** 这是系统设计决策，原因包括：
- **避免表名冲突**：不同数据源可能有同名的表
- **简化查询逻辑**：SQL 生成和执行只需要考虑一个数据源
- **提高准确性**：明确的数据来源可以提高 AI 分析的准确性

### Q2: 如果我想同时分析多个数据源怎么办？

**A:** 有以下几种方案：
1. **创建多个智能体**：每个智能体对应一个数据源
2. **数据整合**：将多个数据源的数据整合到一个数据库中
3. **未来功能**：我们计划在后续版本中支持多数据源联合查询

### Q3: 禁用数据源后，之前的分析历史会丢失吗？

**A:** 不会。禁用数据源只是暂时停用，不会删除：
- 数据源配置信息
- Schema 信息
- 对话历史
- 分析结果

重新启用后，所有信息都会恢复。

### Q4: 如果启用数据源时网络中断怎么办？

**A:** 后端使用了事务机制（`@Transactional`），如果操作失败：
- 所有数据库更改会自动回滚
- 数据源状态保持不变
- 前端会显示错误提示
- 可以重新尝试操作
